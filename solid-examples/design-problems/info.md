## Признаки проблемного дизайна
### Жесткость
Трудно менять код, простое изменение затрагивает много участков кода.

**Признаки:**
- Использование классов напрямую (без асбрактных классов или интерфейсов)
- Магические числа (использование чисел в коде без вынесения в константы)
- Алгоритм работает с конкретным способом ввода-вывода
- Проверка *типа* переменной (при возникновении нового типа нужно добавлять дополнительную ветку) решается абстрактными классами или интерфейсами

### Неподвижность
Сложность разделения кода на переиспользуемые модули. *Например* каждая функция внутри себя вызывает какую-то другую для продолжения работы алгоритма. Таким образом, весь смысл использования функций (переиспользования кода) теряется.

**Признаки:**
- Нарушение принципа единой ответственности классов также является примером неподвижности (весь код в одном классе)
- Использование глобальных переменных вместо параметров функции
- Неграмотное разбиение на функции (спагетти-код) см. пример в определении

### Вязкость
Внести изменения в код с помощью *костыля* (нарушая дизайн) проще, чем добавить код, сохраняя заложенные в преокт принципы. *Например* все константы в одном файле.

### Ненужная сложность
Нарушения, проявляющиеся в виде интерфейса "на все случаи жизни" или наличия неиспользуемой в данной момент функциональности.

**Признаки:**
- Реализация полного спектра методов заранее, когда неизвестно, потребуются ли все они
- Неоправданная разработка универсальных (шаблонных) классов и методов для решения частной задачи
- Функции слишком общего назначения (принимают строку, которую надо распарсить, принимают object, переменное число аргументов)

### Ненужная повторяемость
Отсутствие декомпозиции, которая ведёт к повторяемости кода (сложно поддерживать и больше писать)

### Плохая читабельность
Код должен представлять из себя понятный интерфейс, предназначенный для всех программистов + понимать спустя время.

**Признаки:**
- Отсутствие четкой иерархии между модулями
- Несоблюдение *кодстайла*
- Несогласованность кода, например написание схожих методов с различным интерфейсом
- Отсутствие или несодержательность текста исключений
- Объявление переменных сильно заранее, а не перед их использованием

### Хрупкость
Свойство, при котором незначительные изменения в одной части кода могут привести к ошибкам в другом. Обычно следствие жёсткости и (или) повторяемости

## Лабы
Все лабы состоят из двух программ: одна правильная, другая неправильная, но обе полностью решающие поставленную задачу. Минимум 3 из 7 признаков должны быть нарушены. В правильном варианте всё должно быть ок. Задача ставится самостоятельно на указанную тему. (история, научная фантастика и пр).
